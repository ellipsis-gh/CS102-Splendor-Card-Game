> Auto-generated by context-saver on 2026-03-30

## Overview
A console-based Java implementation of the Splendor board game for 2–4 players, supporting both local (single-machine) and networked (client-server TCP) multiplayer. Players collect gem tokens, buy development cards, reserve cards, and attract nobles to reach the winning prestige score (configurable, default 10 in `config.properties`). The game includes a greedy AI opponent and an ANSI-coloured terminal UI.

## Tech Stack
- **Language:** Java (no build tool — raw `javac`)
- **Library:** `jansi-2.4.1.jar` for ANSI colour on Windows terminals
- **Data:** CSV files for cards and nobles (`data/`)
- **Network:** raw TCP sockets (port 5000 default)
- **Compile scripts:** `compile.bat` (Windows), `compile.sh` (Unix)
- **Run scripts:** `run.bat` / `run.sh` (local), `run_client.bat` / `run_server.bat` / `client_run.sh` / `server_run.sh` (networked)

## File Analysis

### `src/Main.java`
- **Language:** Java
- **Purpose:** Local game entry point. Installs ANSI console support, creates a shared `Scanner` and `ConsoleUI`, prompts for player count and AI flags, then delegates to `GameApp.setupGame()` and `GameApp.runGameLoop()`.
- **Key exports:** `main(String[])`
- **Dependencies:** `jansi`, `logic.Game`, `util.GameApp`, `util.ui.ConsoleUI`

### `src/config/GameConfig.java`
- **Language:** Java
- **Purpose:** Reads `src/config/config.properties` to supply game parameters (winning points, gem counts, noble counts, CSV file paths). Each method opens the file independently.
- **Key exports:** `getWinningPoints()`, `getInitialGems(int)`, `getInitialNobles(int)`, `getCardFilePath()`, `getNobleFilePath()`
- **Dependencies:** `java.util.Properties`, `java.io.*`

### `src/config/config.properties`
- **Language:** Properties file
- **Purpose:** Configures game rules: `winning.points=10`, gem counts per player count, noble counts per player count, CSV file paths.
- **Key values:** `winning.points`, `deck.filePath=data/Splendor Cards.csv`, `nobles.filePath=data/Nobles.csv`

### `src/game/CardLoader.java`
- **Language:** Java
- **Purpose:** Parses `Splendor Cards.csv` (comma-delimited) into `Card` objects and `Nobles.csv` (semicolon-delimited) into `Noble` objects.
- **Key exports:** `loadCards(String path)`, `loadNobles(String path)`
- **Dependencies:** `model.Card`, `model.Noble`, `model.Token`

### `src/game/deckGetter.java`
- **Language:** Java
- **Purpose:** Legacy CSV reader that splits cards into three level groups by line-number ranges (rows 2–41 = L1, 42–71 = L2, 72+ = L3). Not used by the active `GameApp` (which uses `CardLoader` instead).
- **Key exports:** `getDecksByLevel()`
- **Dependencies:** `model.Card`, `model.Token`

### `src/interfaces/IBank.java` / `IBoard.java` / `ICard.java` / `IDeck.java` / `INoble.java` / `IPlayer.java`
- **Language:** Java
- **Purpose:** Interface contracts for each model class. `IPlayer` is the most detailed, specifying the full token/card/noble API.
- **Key exports:** Interface methods (see individual files)

### `src/logic/Game.java`
- **Language:** Java
- **Purpose:** Core game state machine. Validates and executes all moves (take gems, buy card, reserve card, return tokens), manages turn order, implements the end-of-round trigger when someone hits the win score, and determines the winner.
- **Key exports:** `canTakeThreeDifferentGems()`, `takeThreeDifferentGems()`, `canTakeTwoSameGems()`, `takeTwoSameGems()`, `canBuyVisibleCard()`, `buyVisibleCard()`, `canBuyReservedCard()`, `buyReservedCard()`, `canReserveVisibleCard()`, `reserveVisibleCard()`, `canReserveDeckCard()`, `reserveDeckCard()`, `checkAndAwardNoble()`, `endTurnAndCheckNoble()`, `triggerEnd()`, `determineWinner()`
- **Dependencies:** `model.Board`, `model.Card`, `model.Noble`, `model.Player`, `model.Token`

### `src/logic/SplendorAI.java`
- **Language:** Java
- **Purpose:** Greedy AI that evaluates the board each turn and returns a command string. Priority: buy affordable card → buy reserved card → reserve near-affordable card → take needed gems → fallback take 3.
- **Key exports:** `chooseAction(Player, Board)`, `chooseTokensToReturn(Player, Board, int)`
- **Dependencies:** `model.Board`, `model.Card`, `model.Noble`, `model.Player`, `model.Token`

### `src/model/Bank.java`
- **Language:** Java
- **Purpose:** Standalone bank class that manages token counts by player count. Appears to be an earlier design; the active code uses `Board`'s token map directly. Implements `IBank`.

### `src/model/Board.java`
- **Language:** Java

- **Key exports:** `getAvailableTokens()`, `removeToken()`, `addToken()`, `getVisibleCards(int)`, `takeCard()`, `refillMarket()`, `canTakeTwo()`, `canTakeThreeDifferent()`, `drawFromDeck()`, `deckHasCards()`, `getNobles()`, `removeNoble()`

### `src/model/Card.java`

### 2026-03-30 — Gem color visibility fix (background-coloured chips + bold borders)
- **Files changed:** `src/util/ui/ConsoleUI.java`
- **What changed:** Added `gemChip(Token, boolean)` helper that renders a background-coloured chip (e.g. white-bg+black-text for WHITE, black-bg+bright-white for BLACK) used as the bonus indicator inside card boxes. Updated `gemBorderColor()` to use bold foreground for GREEN/BLUE/RED/GOLD and background+contrasting-fg for WHITE/BLACK so borders are always visible. Updated `renderCardBox` bonus line to use `gemChip` instead of `colorizeToken`. Updated `colorizeToken` WHITE from plain `ESC[37m` to bold `ESC[1;37m` for better dark-terminal visibility.
- **Why:** WHITE gem cards had invisible borders/labels on white-background terminals; BLACK gem cards had invisible borders/labels on dark-background terminals. Using background colors guarantees contrast on any terminal theme.
